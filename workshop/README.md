# Материалы воркшопа

Эта папка ведёт вас от идеи до принятой локальной версии приложения.

## Порядок работы

1. Заполните [`problem.md`](problem.md): кто пользователь и что у него не получается.
2. Заполните [`spec.md`](spec.md): что входит в первую версию.
3. Прочитайте [`scenarios.md`](scenarios.md): по ним агент создаст проверки.
4. Используйте готовые запросы из [`prompt-cards.md`](prompt-cards.md).
5. После реализации заполните [`uat.md`](uat.md): примите или отклоните результат.
6. В конце заполните [`transfer-card.md`](transfer-card.md) для своей идеи.

Если проект перестал работать, откройте [`recovery.md`](recovery.md). Карта контрольных точек находится в [`checkpoint-map.md`](checkpoint-map.md).

## Три правила

- Меняем один небольшой фрагмент за раз.
- После каждого изменения проверяем результат.
- Не разрешаем агенту добавлять функции, которых нет в `spec.md`.

## Что означают слова на воркшопе

- **Сценарий** — действие пользователя и видимый результат.
- **RED** — проверка запущена и ожидаемо падает, потому что функции ещё нет.
- **GREEN** — все согласованные проверки проходят.
- **UAT** — человек вручную проверил продукт и принял решение.
- **Контрольная точка** — заранее сохранённая рабочая версия, с которой можно продолжить.
