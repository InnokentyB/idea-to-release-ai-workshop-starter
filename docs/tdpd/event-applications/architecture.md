# Граница первой реализации — локальный прототип

Актуальное расширение DL-107 описано в `roles-and-rework.md`: две локальные роли,
ограничение действий в UI/модели и повторная подача той же заявки. Прежняя
граница без повторной подачи ниже относится к первому прототипу.

Дата: 2026-10-10. Пользователь разрешил писать оставшиеся тесты и приступать к
реализации. Тип первой версии уточняется через вопрос в этом чате, потому что
исходные требования описывают нескольких людей, а стартовый репозиторий локальный.

## Предлагаемый локальный прототип

- Существующий React/TypeScript/Vite; Playwright без смены тестового стека.
- Один экран для демонстрации подачи заявки, решения согласующего и подготовки.
  Эти области не являются системой авторизации или имитацией отдельного входа.
- Единая сущность заявки: идентификатор, название мероприятия, состояние
  согласования, комментарий решения, набор обязательных задач с отметками.
- Готовность и число оставшихся задач вычисляются из состояния и списка задач.
  Отдельные копии состояния для «заявителя» и «согласующего» не создаются.
- Изменение задач разрешено только после согласования, проверяется обработчиком
  действия и UI. Пустой/пробельный комментарий не меняет состояние заявки.
- Хранение в localStorage этого браузера, схема и проверка данных при загрузке;
  нет общей базы или синхронизации людей/устройств.
- Временные задачи отделены от механики согласования, чтобы заменить список.
- Пользовательский текст выводится средствами React, без HTML-интерпретации.
- Ошибка хранения должна быть видна; нельзя утверждать успешное сохранение
  при недоступном storage.
- Откат к предыдущему коммиту возможен без миграции production-данных. Ключ
  локальных заявок отделён от учебного `workshop-event-checklist`.

Назначение согласующего, реальные права и совместная работа не доказаны таким
прототипом. Если пользователь выбирает общую систему, Input остаётся открытым
до решения о пользователях, сервере, хранении, назначении и доступе.

Статус: локальный вариант утверждён пользователем в этом чате 2026-10-10:
«можно в несколько потоков в параллель пойти и сделать уже локальный прототип».
Разрешена реализация и параллельная работа.

Заявок может быть несколько: список выбирает одну заявку; только выбранная
показывает области решения и подготовки. Изменения одной заявки не меняют другую.
Все заявки сохраняются под одним ключом `event-applications-v1`, отдельно от
учебных данных. Повторная подача после доработки пока вне определённого контракта;
интерфейс не должен выдавать её за реализованное действие.

Распределение одного писателя на поверхность: доменная модель/хранение — поток
model; App/styles — interface; дополнительные проверки — tests; интеграция,
статус этапов и документация — основной агент. Все работают в одном checkout
с непересекающимися файлами. Приёмка работы требует тестов и письменной передачи.
