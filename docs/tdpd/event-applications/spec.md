## Временные задачи

Предложены агентом по разрешению S103/DL-103; это не фактический рабочий список:

1. Подтвердить площадку.
2. Согласовать программу.
3. Уведомить участников.
4. Проверить оборудование.

Все четыре обязательны для временной версии. Пользователь пришлёт замену.

## Предлагаемый контракт для первого E2E

Этот раздел фиксирует обозримый черновой интерфейс теста, а не реализованную
авторизацию или одобренную архитектуру:

- Через поле «Название мероприятия» и действие «Подать заявку» создаётся заявка.
- Область «Согласование заявки» показывает заявку «На согласовании», поле
  «Комментарий» и действия «Согласовать» / «Вернуть на доработку».
- В области «Состояние заявки» заявитель видит ту же заявку и её статус.
- При пустом комментарии или одних пробелах действие возврата отклоняется:
  статус в обеих областях остаётся «На согласовании»; видимое сообщение
  «Добавьте комментарий, чтобы вернуть заявку на доработку» объясняет следующий шаг.
- При содержательном комментарии статус в обеих областях становится
  «На доработке». Заявитель видит комментарий согласующего и следующий шаг
  «Исправьте заявку по комментарию и отправьте повторно».

Повторная отправка реализуется и проверяется дополнением RULE-008–010 в
`roles-and-rework.md`. Проверки RULE-003/RULE-004 выполняются в роли согласующего
и сохраняют проверку состояния обеих сторон.

## Граница реализации

Используем существующий browser E2E стек. Пользователь разрешил локальную
реализацию с localStorage, несколькими заявками и одним экраном для демонстрации
действий сторон (DL-106, `architecture.md`). Назначение согласующего, настоящая
авторизация и синхронизация людей/устройств требуют отдельного решения для общей
системы. Локальные области не являются правами доступа.

UAT проверяет понятность причины, следующего шага, решения и готовности.
Точные тексты в автоматике не доказывают удобство интерфейса.

## Контракт дополнительных E2E

Источник: RULE-001/002/005/006/007. Пользователь в этом чате разрешил дописать
остальные тесты и затем приступать к реализации (2026-10-10).

- Область «Подготовка мероприятия» показывает четыре обязательные задачи как
  чекбоксы, текст «Осталось обязательных задач: N» и отдельный статус готовности.
- «На согласовании» и «На доработке»: задачи недоступны для выполнения,
  готовность «Не готово»; инструкция «Подготовка доступна после согласования».
- «Согласовать» устанавливает «Согласовано» для обеих сторон; заявитель видит
  «Можно приступать к подготовке мероприятия». Чекбоксы становятся доступны.
- Статус готовности не смешивается со статусом заявки: согласованная заявка
  с невыполненными задачами ещё «Не готово».
- Только нулевой остаток даёт «Готово». Снятие отметки вновь даёт «Не готово».
- Разные названия мероприятий используют один список задач; текущие тесты
  проверяют это независимыми browser context, а не доказывают многопользовательскую работу.
