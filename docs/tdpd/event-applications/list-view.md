# Полный список заявок

## Источник S108 и решение DL-108

Пользователь в этом чате 2026-10-10 попросил доделать список, чтобы полностью
видеть и просматривать заявки. Источник прочитан, авторитет — продуктовый запрос
владельца. Решение: расширить локальный прототип отдельным обзором всех заявок
и переходом к выбранной заявке, не меняя схему хранения или модель ролей.
Критерий: организатор не должен открывать каждую заявку для понимания общей
картины решений и подготовки. Связано с PROB-001 и RULE-001.

## RULE-011: полный обзор и просмотр

- Обзор доступен обеим ролям по кнопке «Все заявки».
- В области «Все заявки» таблица «Список заявок» показывает каждую сохранённую
  заявку: мероприятие, состояние, решение, оставшиеся обязательные задачи,
  готовность и действие открытия.
- Ожидающая заявка показывает «Ожидает решения», согласованная — «Согласовано»,
  возвращённая — причину возврата. Последний комментарий после повторной подачи
  не выдаётся за новое принятое решение.
- «Осталось: N из 4» и готовность вычисляются по той же канонической заявке.
- Нет ограничения числа отображаемых заявок, скрытого усечения названий или
  комментариев. Длинное содержимое переносится; список прокручивается страницей.
- «Открыть заявку …» открывает выбранную заявку с действиями текущей роли.
  «Вернуться к списку» возвращает обзор с актуальными данными.
- Новая подача по-прежнему открывает её детали. Переход в обзор не меняет данных.
- Пустой обзор показывает «Заявок пока нет». Узкий экран сохраняет доступность
  содержания без горизонтального переполнения страницы.

## Граница и риски

Это проекция существующего массива заявок, без отдельного источника истины,
новых прав, серверной пагинации или миграций. Действия записи остаются в карточке
и проверяются той же моделью ролей. Ошибки storage остаются видимыми.
Полная история согласований, поиск и фильтры не включены в этот запрос.

## Сценарии и приёмка

S108 → DL-108 → PROB-001 → RULE-001/011 → `event-application-list.spec.ts`:

1. Пустой обзор и понятное сообщение.
2. Несколько заявок разных состояний видны вместе с решением и остатком задач.
3. Открытие, исправление и возврат в обзор показывают изменения той же заявки.
4. Готовность и просмотр сохранённого списка после reload отражают данные;
   согласующий может открыть ожидающую заявку и принять решение.

Результаты RED/GREEN будут внесены в `evidence.md`. Для UAT пользователь
просматривает несколько собственных заявок, открывает нужную и возвращается
в список, оценивая полноту и читаемость. Автоматика не заменяет этот вердикт.
