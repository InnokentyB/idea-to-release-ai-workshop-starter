# Сценарии и трассируемость

Новые RULE-008–010 и E2E-ROLE/E2E-REV описаны в `roles-and-rework.md`.
Все прежние сценарии выполняются под ролью соответствующего действия.

Все сценарии связаны с PROB-001. Первая автоматизированная часть — возврат
на доработку; остальные правила остаются видимыми в плане, не объявляются покрытыми.

| Сценарий | Правила | Исходное состояние и действие | Наблюдаемый PASS | Проверка |
|---|---|---|---|---|
| SCN-RET-01 | RULE-003/004 | Заявка на согласовании; согласующий возвращает с пустым комментарием | Статус обеих сторон неизменен; причина и инструкция добавить комментарий видны | `event-application-return.spec.ts`, E2E-RET-01 |
| SCN-RET-02 | RULE-003/004, DL-104 | То же, комментарий из пробелов | Тот же отказ без смены статуса | E2E-RET-02 |
| SCN-RET-03 | RULE-002/003 | Заявка на согласовании; содержательный комментарий и возврат | Обе стороны видят «На доработке»; заявитель видит комментарий и следующий шаг | E2E-RET-03 |
| SCN-APP-01 | RULE-002/005 | Согласующий согласовывает заявку | Обе стороны видят решение; четыре задачи доступны, готовности ещё нет | `event-application-preparation.spec.ts`, E2E-APP-01 |
| SCN-PREP-01 | RULE-001/005 | Заявка ожидает согласования | Четыре задачи видны, не выполнены и заблокированы; оставшиеся 4, «Не готово» | E2E-PREP-01 |
| SCN-PREP-02 | RULE-005 | Заявка возвращена с комментарием | Подготовка остаётся заблокированной, «Не готово» | E2E-PREP-02 |
| SCN-PREP-03 | RULE-001/007 | Согласованная заявка; выполнение каждой задачи, затем снятие одной отметки | Остаток уменьшается; «Готово» только при нуле; снятие отметки возвращает «Не готово» | E2E-PREP-03 |
| SCN-PREP-04 | RULE-006 | Создаются заявки на встречу и семинар в независимых запусках | Одинаковые четыре обязательные задачи | E2E-PREP-04, два набора данных |
| MANUAL-001 | RULE-001/004 | Организатор и заявитель проходят реалистичный процесс | Без чата понимают решение, причину, следующий шаг и готовность | UAT; не начат |
| SCN-LOCAL-01 | DL-106, RULE-001/007 | Согласование и часть задач, перезагрузка | Решение и отметки восстановлены, остаток верен | `event-application-storage.spec.ts`, E2E-LOCAL-01 |
| SCN-LOCAL-02 | DL-106, RULE-001/003/006 | Две заявки с разными решениями, перезагрузка и выбор каждой | Данные, комментарии и задачи не смешиваются | E2E-LOCAL-02 |
| SCN-LOCAL-03 | DL-106 | Браузер запрещает запись, подача заявки | Видна ошибка; долговременное сохранение не заявляется | E2E-LOCAL-03 |
| SCN-LOCAL-04 | DL-106 | Повреждённый JSON или неверная схема в storage | Видимое предупреждение, исходный payload не стёрт | E2E-LOCAL-04, два набора |
| SCN-LOCAL-05 | DL-106 | HTML-подобный текст в названии и комментарии | Текст виден буквально, код не исполняется, в том числе после reload | E2E-LOCAL-05 |

SCN-RET имеют начальную заявку, создаваемую через публичный UI, а не искусственную
запись в storage. Локальное сохранение добавлено после выбора DL-106 и проверяется
SCN-LOCAL. Серверные права и повторная подача требуют отдельного контракта.

Цепочка: S101–104 → F101–107 → DL-101–105 → PROB-001 → RULE-001–007 →
сценарии выше → E2E / MANUAL → `evidence.md` → будущий UAT.
