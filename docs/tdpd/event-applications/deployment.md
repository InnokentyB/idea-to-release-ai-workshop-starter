- `Dockerfile`: два этапа, закреплённый Node 24 Alpine, только build output и сервер в runtime, непривилегированный пользователь, `/health`.
- `.dockerignore`: разрешены только необходимые исходники и build-конфигурация; credentials, `.git`, документация и localStorage не входят в образ.
- `llmdevops.yaml`: stateless-http v1, текущий публичный репозиторий, `codex/event-applications-release`, 8080, `/health`, без application secrets.
- `playwright.release.config.ts`: существующие продуктовые сценарии против `server.mjs` и собранного `dist`, без ослабления тестов.
- `.github/workflows/vibehosting-image.yml`: ручной запуск, linux/amd64, GHCR, полный source SHA и image digest в итогах run.
- Глобальный Codex MCP `vibehosting` подключён через официальный локальный мост. Для нового аккаунта задан отдельный credential-файл `~/.config/vibehosting/tech-analyst-club-account.json`. Код приглашения и токен в проект не записаны.

## Порядок выпуска

1. Завершить UI и получить GREEN: `npm run build`, затем `npx playwright test --config playwright.release.config.ts --workers=2 --reporter=list`.
2. Зафиксировать проверенную версию, отправить её в публичный репозиторий. Если выпускается другая ветка, изменить `source.ref` до коммита.
3. В GitHub Actions вручную запустить **Prepare VibeHosting image** на этой версии. Забрать полный source SHA и `ghcr.io/innokentyb/tech-analyst-club@sha256:…` из итогов. Проверить публичность GHCR-пакета и возможность anonymous pull; первый пакет может быть private.
4. Через MCP `create_account` зарегистрировать новый аккаунт с действующим приглашением. При неоднозначной ошибке сначала проверить наличие локального credential и переподключить мост; не расходовать новый код вслепую.
5. Прочитать schemas доступных после регистрации инструментов; `register_project` получает манифест, точный `sourceCommit` и immutable image. Затем `plan_deployment`.
6. Показать точный план владельцу. По контракту сервиса получить его фразу `DEPLOY plan_…`, затем вызвать `deploy_project` и `deployment_status`.
7. Проверить HTTPS `/health`, загрузку JS/CSS и пользовательский путь: подача → согласование → все задачи → готовность → reload. Получить человеческий UAT.

## Данные и восстановление

Выкатка публикует только приложение. Заявки остаются в localStorage отдельного браузера и origin; локальные записи с localhost не переносятся на хостинг. Переключатель ролей демонстрационный. Политика доступа VibeHost.com к этому сервису не относится.

Для первой выкатки прежнего образа этого приложения нет. При неуспешном health не считать релиз завершённым; сохранить operation ID и ошибку. Для следующих выкаток записать предыдущий source SHA и digest. Автооткат на лендинге сейчас обозначен недоступным; ручной MCP-откат проверять по актуальной schema/плану, не считать гарантированным. Backend-данных и миграций у прототипа нет; откат контейнера не откатывает browser storage.
